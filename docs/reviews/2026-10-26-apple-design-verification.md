# Apple design refresh verification

The implementation starts at `d50b437` on `codex/scoped-liquid-controls`, preserving the preceding authentication, payment and native-control work. The review base is that branch, not the older `main`.

## Product scope

- Shared semantic content surfaces, headings and service rows across timetable, academic and campus pages; score, exam, elective, record, course and account detail presentation.
- Default Today timeline and an account-adjacent Today / All switch; the original week capsules remain on All, without the added heading above them. Current-day filtering uses Shanghai time and a verified week independently of the grid's selected week.
- Academic home contains service entries only; the upcoming-exam card and its separate requests are removed.
- The electricity page must show a complete standalone old electromechanical meter based on the user's final photographic references: black Bakelite housing, hanging lug, deep glass frame, inset nameplate and black mechanical number registers, observation slot, and a lower terminal box with the payment key. Building/room selection and actual balances/amounts are embedded in this object. The native back control remains outside it. Existing amount limits, confirmation, uncertain-order recovery and single-send payment contracts remain in force.
- Record loading uses measured viewport/header geometry. Web authentication close/refresh share native symbol metrics.
- Tab navigation fades while moving 20pt, with native transition coordination and cancellation restoration.
- Optional student name enrichment uses an authenticated campus identity belonging to the same account and cookie generation. It does not block main-tab presentation. Logout also removes the account-bearing teaching-week cache.

## Remaining boundaries

The runtime audit documents an existing ambiguous campus-form result that is retained only in memory. Closing/restarting can lose the pending recovery state and allow a later manual duplicate application. This redesign does not alter that submission contract or automatically retry writes.

Real school account name recovery, real application/upload/payment/enrollment writes, physical-device visual/haptic behavior and on-device VoiceOver were not exercised. Simulator fixtures and successful builds do not establish those outcomes.
