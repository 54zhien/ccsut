# Detail page UI refinement

User-directed visual scope: hide persistent bottom tabs on pushed detail pages;
screen-level score/exam term filters; readable exam dates and concise locations;
obvious enrolled-course term switching and separated capacity segments; campus
creation FABs/native sheets without a backed submission dock; three-drum electricity
amount selection and adjusted payment dock; trailing login send indicator/countdown.

## Implementation

- Shared child chrome hides `.tabBar` and accepts trailing filter controls. Back
  navigation and the prior top material implementation remain in place.
- Score/exam menus default to all terms; selected terms filter actual content and
  scroll to that section. Exam upcoming cards follow the same filter. Removing
  floor descriptions preserves unknown text and room/building identity.
- Selected-course term choice is a full-width labeled menu with calendar, current
  term and chevron. Course metadata, credit pills, status and capacity have explicit
  hierarchy. Capacity segments have a 4pt white gap when both segments exist.
- Campus forms retain native validation/confirmation/unknown-result state machines.
  Native sheet sizing and close-role toolbar placement manage presentation; the
  shared top blur is reused behind the system toolbar. Only the action button
  retains glass styling; its former extra dock backing is removed.
- Electricity uses three native wheel pickers, whole yuan 000–400. Configured
  per-payment/per-day limits may reduce this cap. 000 cannot pay; at 400 tens and
  ones can only be 0. A UI guard requires the displayed integer to equal the
  model's actual amount. Server cumulative daily enforcement is unchanged.
- Transaction/authentication endpoints, payment confirmation, pending receipt
  protection, form submission and login persistence have not been changed.
