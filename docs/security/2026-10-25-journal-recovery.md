# 支付恢复入口：第一阶段

范围：基于 `dfe4f002`，只修改待确认订单的错误分类、读取重试和异常说明入口。
不增加清记录、任意订单号输入、线下确认解锁或新支付接口。正常缴费、确认和回执页面保持原样。

## 恢复边界

- 区分文件读取失败、版本不支持、内容损坏、已知记录缺失，以及原有的存储不可用错误。
  先读取版本头；未来版本即使没有当前 payload，也不会误报成内容损坏。
- 只在明确的文件不存在错误下考虑旧 defaults；不能用 `fileExists == false`
  推断没有订单。失败不修改原 JSON 或旧 defaults。
- 读失败后按账号写独立 `*.json.recovery-block` 标记，使用与 journal 相同的原子写、
  文件保护和排除备份规则。标记没有订单内容；文件名沿用现有账号编码。
  成功落盘后，原文件随后消失及进程重启都不会自动放行。
- 若存储本身无法写入标记，保留进程内阻塞和原记录。**无法保证标记写失败、
  原记录随后被外部删除、再重启这一组合下仍有持久证据。**本功能不提供删除路径，
  不承诺抵抗卸载、整目录丢失或外部恢复覆盖。这需要独立持久化策略，不能靠 UI 确认解决。
  同样，若没有先前失败标记，进程退出期间原 pending 被外部单独删除，新进程也缺少历史证据。
- 成功读到/保存过 pending 的 store 会记住该账号存在未决订单；模型也在同账号跨
  generation 重启时保留“不能接受 nil”的约束。已知订单不能因一次重新登录被遗忘。
- 阻塞时停止认证/费目初始化。重试先验证账号及 generation，只尝试本地读取；读到
  有效 pending 才恢复现有的费目/校区只读初始化，不会自动创建订单、扣款或提交查单。
  nil、未知状态、持续读取失败都不能作为付款解锁依据。
- 原来由服务端完成状态驱动的 `clear(account:orderID:)` 原子墓碑机制不变。
  没有新增对它的 UI 调用，也没有新增清除阻塞标记的动作。

## 界面范围

只在恢复异常时，以卡片替换房间/金额表单和底部缴费栏，显示具体原因、重试读取和
“核实原订单”。后者打开可滚动的处理说明，建议保留 App 数据并通过学校官方渠道核实。
关闭说明仍然阻塞付款。没有订单号输入、清除、重置、已确认到账或继续付款按钮。
DEBUG 预览新增四种合成状态；不访问真实账号或服务器。

## 服务端对账能力：只读核实

核查日期：2026-10-25。只读现有源码、既有抓包的结构和匿名 GET 官方入口；未建单、扣款、
取消订单或复用存储凭据发起认证请求。个人字段值、抓包原文和凭据均未写入本仓库。

| 来源 | 已证明 | 尚未证明 |
| --- | --- | --- |
| 当前 `EcardAPI.swift` | 现有查单为 GET `/charge/pay/getpayinfo?orderid=...`；客户端解析 `orderid`、`status`、`payexpdate`，将 status=1 视为完成 | 这不是完整服务端字段清单；当前模型未验证账号、费目、金额、房间和发生时间的联合归属；不能据此证明某个成功订单对应损坏记录 |
| 既有 `reference/out/ecard-apis2.json` 历史响应 | GET `/berserker-search/search/personal/turnover` 曾返回 HTTP 200、业务 code=200/success=true，分页结构含 records/total/size/current/pages；记录含 sno/fromAccount/tranamt/jndatetime/orderId/thirdOrderId 等字段 | 流水 orderId 与 charge 订单号是否同一命名空间、金额单位、到账与扣款状态、分页完整性/延迟、跨账号授权隔离尚未验证 |
| 同一历史流水样本的结构检查 | 8 条记录均有非空 orderId、sno、金额和时间字段；thirdOrderId 均为空；没有 feeitem/room/building 字段名，文字中未找到电费/电表样本 | 不能用普通消费流水证明电费到账，也不能仅用金额/时间相近来匹配原订单 |
| 本次匿名 GET `https://ecard.ccsut.cn/charge-app/` | 经重定向到 `https://zts.ccsut.cn:443/portal/shortcut.html`，最终 HTTP 200；得到的是网关页面 | 未取得已登录缴费前端 bundle，也未取得新的真实电费查单样本；HTTP 200 不代表已读取缴费系统 |

结论：存在可继续研究的个人流水查询能力，但**尚无足够证据实现无原订单号的自动对账/解锁**。
后续需取得经过授权的真实电费样本，验证订单号关联、账号归属、费目/房间/金额/时间及最终
扣款/到账语义。本阶段不接入该流水接口，也不猜测订单列表端点或状态码。
