# 一卡通会话交接与 CAS 复用实施计划

**目标：** 修复 WebKit 已登录而原生缴费请求被访问网关拦截，并在 App 登录后复用 CAS 尝试预取缴费凭证。

**依据：** 用户校园网真机提示「加载缴费项目：接口返回了网页（HTTP 200，HTML，学校访问网关）」。当前 EcardClient 使用默认 URLSession，未接收 WebStore 中刚完成登录的 Cookie；已有教务 API 使用显式 CookieJar，避免系统 Cookie 池遗漏。

**实现选择：** EcardClient 增加可注入的传输函数，保留原请求和解析/支付规则；页面 model 的传输复用 CookieJar 的域/路径匹配与账号代数。凭证交接前读取相同 WebStore 的学校 Cookie，并合并到 CookieJar。原生缴费请求禁止自动重定向，避免把认证头或支付表单转给网关；过期时明确要求认证。

**登录复用：** 主账号身份验证完成后，使用相同 WebStore 启动有时限的后台预取，仅缓存符合当前学号和有效期的 JWT。在官方 `/plat` 页面按已观察到的精确入口文字自动进入「智林cas」和电费项目，每个入口一次；不填写凭据，不点击支付或确认。失败不阻挡 App 登录，交互登录保留。打开缴费页时取消后台预取，优先复用已得到的凭证；重新加载先复用凭证，明确认证失效才清除。

**文件职责：** EcardAPI.swift 传输注入与认证失效错误；EcardTokenBridge.swift 官方入口与受账号约束的后台预取；EcardPaymentModel.swift Cookie 交接、原生会话隔离和失效处理；Session.swift 已验证身份后触发预取；EcardPaymentView.swift 更新登录提示文字。

**约束：** 维持现有 UI、金额和二次确认/支付待确认处理；退出取消预取、清凭证并隔离旧 WebStore。用户要求先不测试，本轮不新增/运行测试或真实支付，仅静态核对和 Release 编译打包。实际网关会话、自动入口及学校重新验证策略仍待手机确认。
