# 一卡通电费缴费试用版

用户要求：接到现有教务页，沿用当前风格，先做一版试用，先不测试。

基线：最新教务 UI 分支 0a18c34；接入已修复的 API/登录桥接 2fa81ab，API 文件保持原样。以现有 AcademicView 服务卡片、AcademicDetailChrome、分组背景、28pt 圆角和原生玻璃按钮为视觉依据，保持教务页现有入口顺序，电费入口放在选课下方。

页面：缴费房间（单校区隐藏校区选择）、电表三行信息与红色欠费、留空的金额输入及服务端快捷金额、底部缴费按钮。首次通过独立 WebKit sheet 完成一卡通认证，沿用现有悬浮关闭控件与大圆角。

流程：独立 model 管理加载和级联选择，切换上级立即清除下游并取消旧请求。二次确认冻结房间、上下文和金额；支付期间禁止关闭确认弹窗和重复提交。结果分成功、失败、待确认；待确认订单按学号保存在本地并仅允许查单，重新进入也不会默认再次扣款。

交付：不新增或运行测试，不运行 UI 截图或真实缴费。提交使用 [skip ci] 避免自动测试，仅手动触发 Build IPA 工作流做 Release 编译和试装包。

试用反馈：df2920d 在手机登录 sheet 直接显示 `401 / 缺失令牌，鉴权失败`。交接中「未登录访问 toAppitem 会自动跳转登录」的假定不成立。修正为先进入已记录的官方 `/plat/login` 入口，由用户完成门户登录并打开电费项目，再捕获原有 charge-app 令牌跳转；增加 WKUIDelegate 接管官方新窗口链接和底部操作说明。本机外网访问被 aTrust 网关重定向，不能据此宣称已验证校园网/手机登录。继续仅编译打包，实际登录待用户确认。

第二次试用反馈：用户在校园网，点击「智林cas」可进入门户首页，进入电表缴费后返回原生页报「数据解析失败：数据损坏」。按当前代码，返回原生页表示桥接已交出符合账号/有效期检查的凭证，随后并发加载项目和校区；该错误不足以证明哪一个接口失败，也无法区分 HTML 登录页和无效 JSON。先补充解析失败诊断（操作名称、HTTP 状态、固定响应类型及目标分类），不输出正文、令牌、学号、Cookie、完整 URL，也不根据外网网关结果猜测校园网行为。错误文字支持选择复制。此提交仅用于取得下一次手机响应证据，尚未修复或验证根因；保持请求地址、认证和缴费逻辑不变，仅编译打包，不运行测试。

后续真机反馈：用户重新登录后打开电表缴费只短暂显示窗口，无须再次登录；请求已收到 HTTP 200 JSON（目标为一卡通接口），报 `类型不匹配 @feeitem.feeitemid`。当前 FeeItem 将编号声明为 String 并使用合成 Decodable，只能接收 JSON 字符串。改为在读取边界兼容字符串或整数编号；校区/楼栋/房间选项 value、层级 code/level 同类处理；金额限额兼容字符串或 Decimal 数字，不经 Double。字符串保留前导零，缺失/空值/布尔/对象/数组仍报错，编号不接受小数；不调整登录、UI 或支付规则。继续仅编译打包，不新增/运行测试或真实支付。
